# Suricata IDS Investigation Report

## 1. Overview

This project demonstrates a controlled Network Intrusion Detection System (NIDS) lab using Suricata. Custom detection rules were created to identify network reconnaissance, repeated SSH connection attempts, and suspicious SQL injection patterns.

Traffic was generated from a Kali Linux testing machine and monitored by Suricata running on Ubuntu Linux. Alerts were collected in `eve.json` and reviewed using EveBox.

## 3. Detection 1 — Nmap SYN Scan

### Objective

Detect network reconnaissance activity generated using an Nmap TCP SYN scan.

### Test

A controlled Nmap SYN scan was performed from Kali Linux against the Suricata monitoring host.

### Detection

- Alert: `LOCAL Nmap SYN Scan Detected`
- Signature ID: `1000002`
- Protocol: TCP
- Source: `192.168.50.128`
- Destination: `192.168.50.131`
- Interface: `ens33`
- Severity: 3

### Investigation

TCP SYN packets generated by the Kali system were observed by Suricata. Multiple connection attempts triggered the custom detection rule and were recorded in Suricata logs and EveBox.

### MITRE ATT&CK

**T1046 — Network Service Scanning**

This technique covers activity used to identify available network services and ports on a target system.

## 4. Detection 2 — Repeated SSH Connections

### Objective

Detect repeated TCP connection attempts toward the SSH service.

### Test

Three controlled TCP connection attempts were generated from Kali Linux toward TCP port 22 on the Suricata host.

### Detection

- Alert: `LOCAL Repeated SSH Connection from Kali`
- Signature ID: `1000003`
- Protocol: TCP
- Source: `192.168.50.128`
- Destination: `192.168.50.131:22`
- Interface: `ens33`
- Severity: 3
- Revision: 3

### Investigation

tcpdump was used to confirm the TCP SYN packets generated by the Kali system. Suricata detected the repeated connection attempts and generated an alert that was visible in EveBox.

This rule detects repeated SSH connection attempts. It does not confirm a successful login, password attack, or credential compromise.

## 5. Detection 3 — SQL Injection Pattern

### Objective

Detect suspicious SQL injection-style input within HTTP requests.

### Test

A controlled HTTP request containing a Boolean SQL injection-style pattern was sent from Kali Linux to the test HTTP service.

### Detection

- Alert: `LOCAL Possible SQL Injection Boolean Pattern`
- Signature ID: `1000004`
- Protocol: TCP
- Source: `192.168.50.128`
- Destination: `192.168.50.131:80`
- Interface: `ens33`
- Severity: 3
- Revision: 3

### Investigation

The HTTP request contained a suspicious Boolean SQL expression that matched the custom PCRE detection rule. Suricata generated an alert and the event was reviewed through EveBox.

The detection indicates suspicious SQL injection-style input. It does not prove that successful SQL injection exploitation occurred.

## 8. Key Findings

### Nmap Detection

Suricata successfully identified the controlled Nmap SYN scan generated from Kali Linux.

### SSH Detection

Repeated TCP connection attempts to the SSH service were successfully detected using a custom Suricata rule.

### SQL Injection Detection

A suspicious Boolean SQL injection-style HTTP request was successfully detected using HTTP URI inspection and a custom PCRE pattern.

## 9. Conclusion

The project successfully demonstrated the deployment and configuration of Suricata as a Network Intrusion Detection System.

Three custom detection rules were created and validated against controlled traffic:

1. Nmap SYN reconnaissance
2. Repeated SSH connection attempts
3. SQL injection-style HTTP input

The alerts were validated using Suricata logs, tcpdump, and EveBox. The project also demonstrates custom rule creation, network traffic analysis, alert investigation, and MITRE ATT&CK mapping.

All testing was performed in a controlled virtual laboratory environment for educational and defensive security purposes.
